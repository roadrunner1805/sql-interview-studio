Interview Coaching Hint

Customer 2 has $1,300 across all orders, but $400 is 'pending'. Use WHERE status = 'completed' BEFORE GROUP BY so pending/cancelled orders are excluded, then use HAVING SUM(order_amount) > 1000 after grouping.

Reference Solution Query 
SELECT customer_id,
       SUM(order_amount) AS total_amount
FROM orders
WHERE status = 'completed'
GROUP BY customer_id
HAVING SUM(order_amount) > 1000
ORDER BY total_amount DESC;

SQL Interview Quick Tips & Cheat Sheet

Core patterns for BA, Data Analytics & Data Engineering interviews

1. Query Execution & Clause Order

FROM / JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

  • WHERE vs. HAVING: Use WHERE to pre-filter raw row attributes before grouping (WHERE status = 'completed'). Use HAVING to post-filter aggregated functions (HAVING SUM(order_amount) > 1000).
  • GROUP BY Golden Rule: Whenever SELECT includes an aggregate function alongside a category column, group by the category column alone—never put an aggregate inside GROUP BY.

2. JOINs & The Anti-Join "Bouncer" Pattern

  • INNER JOIN: Use when looking only at active/matching records across both tables ("at least 1").
  • LEFT JOIN + IS NULL: Use to preserve all left-table rows or find missing/disqualified records.
  • The Bouncer Rule: Put right-table disqualifying filters inside ON ... AND (e.g., AND a.audit_year = 2026 AND a.audit_status = 'passed'). Put left-table filters and AND a.audit_id IS NULL inside WHERE. Putting right-table conditions in WHERE turns your LEFT JOIN into an INNER JOIN!

3. Conditional Aggregation & Zero-Safe Math

  • Counting Matching Rows: SUM(CASE WHEN condition THEN 1 ELSE 0 END) or COUNT(DISTINCT CASE WHEN condition THEN id END). Always close with END.
  • Handling NULLs: COUNT(DISTINCT col) returns 0 when there are no matches, whereas SUM(col) returns NULL—wrap it in COALESCE(SUM(col), 0).
  • Zero-Safe Percentage Formula: ROUND(numerator * 100.0 / NULLIF(denominator, 0), 2). Multiplying by 100.0 avoids integer truncation; NULLIF(..., 0) prevents division-by-zero crashes.

4. CTE Scope & Window Functions Anatomy

  • Inside the CTE (Prep Kitchen): Perform raw table joins, raw WHERE filters, and GROUP BY aggregations.
  • Outside the CTE (Serving Plate): Only reference columns explicitly exposed in the CTE's SELECT. Drop old table prefixes (m., p.) and filter window ranks (WHERE rn = 1) or WHERE prev_val IS NOT NULL here.
  • Window Functions: ROW_NUMBER() for strict single top/latest per partition; DENSE_RANK() for Top-N leaderboards including ties; LAG(col) OVER (PARTITION BY grp ORDER BY date ASC) for period-over-period comparisons.
